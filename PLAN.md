# Bandwidth Limiting Plan

## Decision

Implement application-level streaming throttling with two independent, shared byte budgets. This approach works for native Python and Docker deployments without additional privileges.

Use bounded-burst pacing rather than relying only on yt-dlp's built-in `ratelimit`. The built-in option limits average transfer speed, is not shared across concurrent streams, and does not cover ffmpeg network-download fallbacks.

This feature will limit bulk media transfers:

- YouTube media downloads
- Initial Internet Archive media uploads
- Internet Archive recovery uploads

It will not limit channel scans, Discord requests, Wayback or Ziggy submissions, protocol overhead, or traffic generated by a separate Ziggy service.

## Configuration

Add two process-wide settings:

| Variable | Meaning | Default |
| --- | --- | --- |
| `SAGA_DOWNLOAD_BYTES_PER_SECOND` | Combined allowance for media downloads | `0` (unlimited) |
| `SAGA_UPLOAD_BYTES_PER_SECOND` | Combined allowance for media uploads | `0` (unlimited) |

Both values are non-negative integers measured in payload bytes per second. Reject negative values, fractions, empty values, and non-numeric values during startup. Each direction operates independently, and changes require a restart.

Example for a 50 Mbps download allowance and 10 Mbps upload allowance:

```dotenv
SAGA_DOWNLOAD_BYTES_PER_SECOND=6250000
SAGA_UPLOAD_BYTES_PER_SECOND=1250000
```

The limits apply per Saga process, not per channel, request, transfer, or archive worker.

## Shared Limiter

Add a small thread-safe byte limiter, likely in `core/bandwidth.py`.

Requirements:

- Use a monotonic clock.
- Share one limiter among all media downloads and a separate limiter among all media uploads.
- Bound accumulated credit so idle time cannot create an unlimited burst.
- Split large acquisitions into bounded chunks so low configured rates remain usable.
- Reserve allowance before transferring each chunk.
- Keep lock-held sections short and perform waits outside the lock.
- Allow an unlimited mode with no sleeping or accounting overhead in transfer paths.
- Retain streaming behavior and never buffer an entire media file.
- Keep deterministic tests possible by injecting clock and wait functions.

## Download Integration

Apply the download limiter only to `YouTubeClient.download_video()` in `core/youtube.py`. Channel discovery and metadata scans are outside the selected media-transfer scope.

Create a scoped `YoutubeDL` subclass or equivalent factory that wraps responses returned by `YoutubeDL.urlopen()`. The response wrapper must pace reads through the shared download limiter.

Requirements:

- Handle `read(size)` and unbounded `read()` calls without allowing an unbounded network read.
- Preserve response headers, status, URL, extensions, close behavior, and yt-dlp transport errors.
- Share one budget across direct HTTP transfers, fragments, selected audio and video streams, retries, and resumes.
- Keep yt-dlp's existing local file handling and ffmpeg merge behavior unchanged.
- Do not also enable yt-dlp's `ratelimit`, which would apply a second independent pacing mechanism.

Saga currently serializes complete media downloads with `ArchiveProcessor._download_lock` in `core/archival.py`. The shared limiter still protects against yt-dlp paths that use multiple internal streams or fragment workers.

### External Downloader Guard

Python response wrapping cannot see sockets opened by ffmpeg. When a download limit is enabled:

- Prefer yt-dlp's native downloaders.
- Keep fragment concurrency explicit and bounded.
- Prohibit ffmpeg from using network protocols through supported external-downloader arguments.
- Allow ffmpeg to merge already downloaded local files.
- Fail the transfer if the exact selected formats require an uncapped external network downloader.
- Do not silently choose lower-quality formats because Saga promises yt-dlp's exact `bestvideo+bestaudio` selection.

Add tests for direct HTTP, native HLS or DASH fragments, retries, resumed files, and attempted external downloader fallback.

## Upload Integration

Apply the upload limiter at the Niquests transport boundary used by `ArchiveGateway` in `core/archival.py`.

Add a small `HTTPAdapter` subclass that wraps streaming media PUT request bodies. The wrapper acquires upload allowance before yielding each chunk to the transport.

This boundary is required because Archivist recovery mutations call `session.get_adapter(url).send(...)` directly. Overriding only `Session.request()` or `Session.send()` would miss recovery uploads.

Requirements:

- Share one upload limiter among every archive worker and session.
- Preserve `Content-Length` and exact media bytes.
- Wrap media PUT bodies only, leaving login, metadata, polling, and other control requests outside the media cap.
- Keep local validation and recovery checksum reads unthrottled.
- Keep adapter and session retries disabled so archive mutations remain one-shot.
- Use fresh sessions for archive operations and close them explicitly because Archivist does not close caller-supplied sessions.
- Inject the session into every Archivist client used for initial and recovery uploads.
- Declare Niquests as a direct dependency if Saga imports or subclasses it.

Do not implement upload limiting by wrapping the source file globally. Archivist hashes recovery files before network transfer, so a generic throttled file wrapper would consume upload allowance during local disk reads.

## Recovery and Shutdown

Keep the existing archive state machine and timeout behavior for the first implementation.

Archivist's recovery deadline can expire after a deliberately slow transfer. Saga already classifies polling timeouts as temporary, persists the recovery outcome, and re-inspects the remote item before attempting another transfer. Add a regression test proving that an acknowledged transfer followed by deadline expiry reaches verification without a second mutation.

Do not calculate an automatic timeout from file size and configured rate. A bandwidth ceiling is not a minimum-throughput guarantee and cannot bound server or network delays.

Keep the current drain-on-shutdown behavior. Do not make limiter waits throw arbitrary exceptions during an active upload, because Saga could misclassify an uncertain mutation as a preflight failure. Document that low limits can make active transfers exceed the Docker example's 30-second stop grace period.

## Wiring

1. Add defaulted bandwidth fields to `Settings` in `core/config.py`.
2. Parse and validate both environment variables in `load_settings()`.
3. Construct mutable limiter state during application composition, not inside `load_settings()`, because the health-check process also loads settings.
4. Pass the download limiter to `YouTubeClient`.
5. Pass the upload limiter to `ArchiveGateway`, directly or through `ArchiveProcessor` construction.
6. Update `.env.example` and the README environment-variable table.
7. Explain units, zero behavior, per-process scope, restart requirements, bounded bursts, and exclusions in the preservation documentation.

## Testing

Configuration tests:

- Both values default to zero.
- Zero explicitly disables a direction.
- Upload and download can be enabled independently.
- Positive integer values are accepted.
- Negative, fractional, empty, and non-numeric values are rejected with the variable name in the error.
- Process environment values retain precedence over `.env` values.

Limiter tests:

- Unlimited mode does not wait.
- Allowance refills according to a fake monotonic clock.
- Accumulated burst credit is bounded.
- Requests larger than the burst capacity are split and complete.
- Concurrent threads share one aggregate allowance.
- Upload and download budgets are independent.
- Tests use fake time and do not sleep in real time.

Download integration tests:

- All native media response reads consume the shared budget.
- Multiple streams and fragments share one allowance.
- Retries and resumed transfers remain limited.
- Unbounded response reads are split into bounded reads.
- External network download fallback fails closed when limiting is enabled.
- Local ffmpeg merging remains available.
- Unlimited mode preserves current yt-dlp options and behavior.

Upload integration tests:

- Initial uploads consume the shared upload budget.
- Recovery uploads using direct adapter dispatch also consume the same budget.
- Concurrent archive workers do not multiply the configured rate.
- Request content length and body bytes remain unchanged.
- Local hashing and control requests consume no upload allowance.
- Adapter retries are disabled and supplied sessions are closed.
- A recovery deadline after acknowledged transfer results in re-inspection rather than another immediate upload.

## Enforcement Limits

The implementation will enforce bounded media-payload throughput. It will not be an instantaneous network-interface ceiling. Socket buffers and protocol overhead can create short bursts, and upload acknowledgements consume download traffic outside the media cap.

Set both allowances below the connection's measured usable capacity to retain headroom for other applications and control traffic.

A literal cap covering every packet, library, subprocess, and protocol requires traffic shaping on the host or network gateway. That option is separate from this application-level feature and is not part of this plan.
